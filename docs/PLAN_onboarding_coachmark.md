# 온보딩 코치마크 기획서

> 구현 착수 전 기획 단계. 승인 후 구현.
> 목표: 사용법 가이드(3장) 직후, 실제 앱 화면 위에서 주요 기능을 **아주 짧고 빠르게** 안내.

---

## 0. 핵심 제약 (사용자 확정)

- **4번 이하 클릭**으로 끝나야 함 → 스텝은 **최대 4개**.
- **정보량 최소화** → 스텝당 짧은 제목 1줄 + 보조 1줄. 장문 금지.
- 언제든 **건너뛰기** 가능.
- 최초 1회만. 계정/기기 단위로 다시 안 뜸.

---

## 1. 무엇인가 (기존 사용법 가이드와의 차이)

| | 사용법 가이드(기존 `usage_guide`) | **코치마크(신규)** |
|---|---|---|
| 형태 | 전체 화면 3장, 목업 카드 | 실제 홈 화면 **위에 스포트라이트 오버레이** |
| 시점 | 가이드 3장 넘기는 중 | 가이드 끝난 **직후 홈 화면에서** |
| 대상 | 개념 설명 | 실제 버튼/영역을 손가락으로 짚어줌 |

→ 코치마크는 가이드를 대체하지 않고, 가이드 직후 "이 버튼이 그 기능이에요"를 연결해준다.

---

## 2. 진입 흐름

```
usage_guide (3장) ─ 시작하기 ─▶ completeUsageGuide() ─▶ stage='app' ─▶ MainScreen(홈)
                                                                          │
                                                     첫 빌드 시 _kCoachMarkSeen==false 면
                                                          ▼ 코치마크 오버레이 표시
```

- `stage`에 붙이지 않는다. 코치마크는 **라우트가 아니라 오버레이**.
- 트리거: `MainScreen` 첫 빌드 후 `SharedPreferences`의 `_kCoachMarkSeen` 확인 → false면 표시.
- 끝나면(완료/건너뛰기) `_kCoachMarkSeen=true` 저장. (기존 `_kUsageGuideSeen` 패턴 그대로)

---

## 3. 코치마크 스텝 (4개로 압축)

5개 기능(필터/혼잡도/제보/지도/스탬프)을 **자연스럽게 묶어 4스텝**으로.

| # | 스포트라이트 대상 | 제목(1줄) | 보조(1줄) |
|---|---|---|---|
| 1 | 홈 상단 **필터 행**(정렬·지역·음식) | 원하는 조건으로 걸러봐요 | 내가 원하는 조건의 매장을 찾을 수 있어요 |
| 2 | **첫 매장 카드의 혼잡도 뱃지** | 혼잡도를 한눈에 확인 | 바로 입장 가능한 매장을 확인해보세요 |
| 3 | 홈의 **스탬프 요소** | 제보하고 스탬프 적립 | 모으면 커피 쿠폰으로 교환해요 |
| 4 | 하단 **지도 탭 아이콘** | 지도로도 볼 수 있어요 | 내 주변 매장을 지도에서 한눈에 |

- **제보하는 법은 홈 코치마크에서 생략(확정)**. 제보는 카드탭→상세화면→제보버튼 순으로 들어가야 뜨는 화면이라, 홈 오버레이로는 실제 제보 시트를 보여줄 수 없음. 탭을 넘나드는 인터랙티브 플로우로 확장하는 대신, 4클릭 제약과 "탭 안 넘나듦" 원칙을 지키기 위해 안내 자체를 생략하기로 함.
- 각 스텝: 대상 영역만 밝게(스포트라이트), 나머지 어둡게. 말풍선 + "다음"(마지막은 "확인"). 우상단 "건너뛰기".
- 탭하면 다음. 4번째에서 완료.

### 시각 스타일 (레퍼런스 이미지2 — 네이버 홈 편집 방식 확정)
- **하나씩 스포트라이트**: 어두운 반투명 배경(약 60~70% 검정) + 대상 영역만 뚫어서 밝게.
- 대상 옆에 **손가락(탭) 포인터 아이콘** + 브랜드 그린 원형 하이라이트(레퍼런스의 파란 원 → 우리 앱은 `#9ECA8B`/`#5E8C4A` 톤).
- 짧은 **말풍선**(제목 굵게 1줄 + 보조 회색 1줄). 대상 위치에 따라 말풍선을 위/아래로 자동 배치.
- 진행 표시: 하단에 점 인디케이터(기존 usage_guide와 동일 토큰) 또는 "1/4" 텍스트.
- 배경 아무 곳이나 탭해도 다음으로(레퍼런스처럼 가볍게 넘기기), 우상단 건너뛰기는 전체 종료.

## 4. 구현 방식 (새 패키지 없음)

- 코드베이스에 코치마크 패키지 없음 확인됨 → **`OverlayPortal`로 직접 구현**.
  홈 화면이 이미 `OverlayPortalController` + `LayerLink`를 쓰고 있어(혼잡도/스탬프 정보 팝업) 동일 메커니즘 재사용.
- 대상 위젯 위치를 잡기 위해 **`GlobalKey`** 부여 후 `RenderBox`로 화면 좌표 계산 → 그 사각형만 파내는 스포트라이트(어두운 배경 + `BlendMode.clear` 또는 `CustomPainter` 홀).
- 파일:
  - `lib/widgets/coach_mark_overlay.dart` — 스포트라이트 + 말풍선 + 스텝 컨트롤(범용)
  - `lib/models/coach_mark_step.dart` — 대상 key, 제목, 보조, 말풍선 위치
  - 스텝 정의는 `home_screen.dart`(또는 `main_screen.dart`)에서 주입.

### 필요한 GlobalKey (정확히 이것들만)
1. 홈 필터 행 컨테이너
2. 첫 매장 카드의 혼잡도 뱃지 (리스트 첫 항목)
3. 홈 스탬프 요소 (`_stampInfoLink` 근처)
4. 하단 지도 탭 아이콘 (`main_screen.dart`의 `_NavTab`)

---

## 5. 엣지 케이스

- **홈 리스트가 비었거나 로딩 중** → 스텝 2(첫 카드 혼잡도 뱃지) 대상이 없음.
  - 처리: 대상 key의 `RenderBox`가 없으면 그 스텝은 **자동 건너뜀**(또는 말풍선만 화면 중앙에). 코치마크가 깨지지 않도록.
- **사장님 계정** → 별도 처리 불필요(사용자 확정). 유저로 가입 시점에 이미 코치마크를 봤고 `_kCoachMarkSeen`가 계정/기기 단위라 사장님 인증 후 다시 안 뜸.
- **지도 탭 아이콘(스텝 4)**은 홈에 머문 채 아이콘만 가리킴 → 지도 PlatformView 마운트 문제와 무관(탭 이동 안 함).

---

## 6. 하지 않는 것 (스코프 제한)

- 탭을 넘나들며 안내하지 않음(오버레이가 탭 전환을 넘어가면 취약). 전부 **홈 화면 + 하단 탭 아이콘** 범위에서.
- 커뮤니티 탭은 아직 없으므로 코치마크 대상에서 제외.
- 지도 내부 요소, 제보 시트 내부는 짚지 않음.

---

## 7. 열린 항목 (기본안으로 진행, 이견 시 알려주세요)

- 말풍선 카피는 위 표가 기본안. 문구 다듬을 부분 있으면 수정.
- 스텝 순서: 필터 → 혼잡도 → 스탬프 → 지도(기본안). 바꾸고 싶으면 알려주세요.
