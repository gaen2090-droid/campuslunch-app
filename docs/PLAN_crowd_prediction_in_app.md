# 기획안: 매장별 혼잡도 예측을 앱에 보여주기

상태: **기획 확정 · 구현 진행 중 (3단계까지 코드 완료)**
최초 작성 2026-10-15 · 확정 2026-10-18

---

## 한 줄 요약

제보가 없거나 오래된 가게에는, 과거 점심 제보로 계산한 **여유로울 확률**을 `예측` 배지로 보여준다.
새 제보가 들어오면 바로 진짜 제보로 바뀐다.

---

## 1. 언제 보여주나

- **평일 11:30 ~ 13:00**에만 보인다. 13:00이 되면 사라지고 원래 모습으로 돌아간다.
- 11:30부터 15분씩 6개 구간으로 나눠 계산한다.
  (11:30 / 11:45 / 12:00 / 12:15 / 12:30 / 12:45)
- 그 구간에 **제보가 3건 이상** 쌓인 가게만 예측한다. 부족하면 예측하지 않는다.
- 예측을 보여주는 가게는 둘 중 하나다.
  - 오늘 제보가 한 건도 없는 가게
  - 마지막 제보가 30분 넘게 지난 가게
- 30분 이내 제보가 있는 가게는 제보를 그대로 보여주고, 예측은 붙이지 않는다.
- 예측이 없는 가게(제보 부족, 시간 밖)는 지금과 똑같이 둔다.

## 2. 확률은 어떻게 나오나

- 바로입장 1점 · **약간혼잡 0.6점** · 자리없음 0점으로 계산한다.
- 제보가 적을 때 확률이 극단으로 튀지 않도록 보정한다.
- 계산은 서버 한 곳에서만 하고, 앱과 어드민이 같은 기준을 쓴다.
- 확률에 따라 이렇게 나눈다.

| 여유로울 확률 | 들어가는 곳 |
|---|---|
| 70% 이상 | 바로 입장 가능해요 |
| 40 ~ 69% | 빈자리 조금 있어요 |
| 40% 미만 | 붐비고 있어요 |

## 3. 홈 화면

- 예측 가게는 확률에 따라 위 표의 섹션에 들어간다.
- 같은 섹션 안에서는 **30분 이내 제보 가게가 위**, **예측 가게는 아래**(확률 높은 순)에 놓인다.
- 예측 가게에는 작은 배지를 붙인다. **숫자는 보이지 않는다.**
  - `예측 · 바로입장`
  - `예측 · 약간혼잡`
  - `예측 · 자리없음`
- `혼잡도를 알려주세요` 섹션에는 **오늘 제보가 0건인 가게만** 들어간다.
  - 예측이 있어도 0건이면 여기에도 들어간다. 그래서 홈에서 두 번 보일 수 있다.
  - 제보가 한 건이라도 있으면 들어가지 않는다.
  - 이 섹션의 `제보하면 스탬프 2개` 표시는 그대로 둔다. 예측 카드에는 붙이지 않는다.
- 추천 배너, 점메추 요정, 룰렛에는 예측을 쓰지 않는다. 확인된 제보만 쓴다.

## 4. 상세페이지

- **지금 여유로울 확률 82%** 같은 숫자는 여기서만 보여준다. 위치는 최근 제보 바로 위다.
- 안내 문구 하나를 함께 넣는다.
  > 이 시간대에 쌓인 제보로 계산한 확률이에요.

## 5. 지도

- 예측 가게는 확정 제보와 **같은 색 마커**(초록 / 앰버 / 빨강)로 나온다. 점선은 쓰지 않는다.
- 마커 **바로 위 정중앙에 작은 `예측` 태그**를 붙인다.
  - 작은 크기에서 읽히는지는 그림 시안이 아니라 **실제 앱에서 직접 확인**한다.
- 가게를 눌렀을 때 나오는 카드에는 숫자 없이 같은 예측 배지를 두고, 그 바로 아래에 `이 시간대에 쌓인 제보로 예측한 혼잡도예요.`를 작은 글씨로 넣는다. 범례에는 설명을 넣지 않는다(폭이 넓어져서).
- 필터 칩줄에 **`스탬프 2개` 칩**(별 아이콘)을 새로 만든다.
  - 필터 칩줄 **맨 앞**에 둔다 (`카페`, `즐겨찾기`보다 앞).
  - 켜면 오늘 제보가 0건인 가게만 남는다.
  - 초기화 버튼을 누르면 이 칩도 꺼진다. 켜 둔 상태는 다른 칩처럼 기억한다.
  - 해당하는 가게가 없으면 칩을 숨긴다.
- 0건 가게 중 예측이 있는 곳은 색 마커로, 예측이 없는 곳은 지금처럼 검정 별 마커로 나온다.
- 시간대를 고르는 칩은 이번에는 만들지 않는다.

## 6. 스탬프

- **스탬프 2개는 오늘 제보가 0건인 가게에만** 준다. 지금 규칙 그대로다.
- 예측이 있어도 0건이면 똑같이 받고, 오래된 제보만 있는 가게는 대상이 아니다.

## 7. 갱신

- 앱이 예측을 **평일 11:20 ~ 13:00 동안 90초마다** 새로 받아온다. (잠정)
- "실시간"이라는 말은 쓰지 않는다. 필요하면 `제보가 쌓이면 바로 바뀌어요`라고 쓴다.

---

## 8. 지금 앱 상태 (참고)

- 홈 섹션 순서: 바로 입장 가능해요 → 빈자리 조금 있어요 → 혼잡도를 알려주세요 → 붐비고 있어요 → 영업 종료
- 30분이 넘은 제보만 있는 섹션은 `30분 이상 지난 제보예요.`라고 표시된다.
- `혼잡도를 알려주세요`는 "이번 영업 시작 후 제보가 0건"인 가게가 들어간다. 시간 기준이 아니다.
- 지도 마커: 바로입장 초록 · 약간혼잡 앰버 · 자리없음 빨강 · 제보필요 검정 원+흰 별 · 영업안함 회색
- 지도 필터 칩은 카페 / 즐겨찾기 / 정문·중문·후문 / 음식종류뿐이다. `제보없음` 칩은 화면에 없다.
- 앱에는 실시간 자동 갱신이 없다. 앱으로 돌아올 때나 제보 후에 새로 받는다.

## 9. 검토했다가 접은 안

| 안 | 접은 이유 |
|---|---|
| 예측 전용 섹션을 따로 추가 | 홈 섹션이 이미 많아서 묻힘 |
| 예측 가게를 `혼잡도를 알려주세요`에서 빼기 | 0건 가게는 제보를 유도해야 해서 유지 |
| 예측에 숫자(82%) 표시 | 홈은 배지만, 숫자는 상세페이지에서만 |
| 지도에 점선 테두리 | 작은 마커에서 잘 안 보임. `예측` 태그로 대체 |
| 1시 이후에도 마지막 예측 유지 | 점심 피크 예측이 오후에 남으면 틀린 정보가 됨 |
| 약간혼잡 0.7점 | 약간혼잡만 쌓인 가게가 67%로 초록 기준(70%)에 붙어버림. 0.6으로 정함 |
| `제보필요`를 `데이터부족`으로 이름 변경 | 제보하라는 행동 유도가 사라짐 |

## 10. 만드는 순서

개발 중에는 평일 11:30 ~ 13:00에만 예측이 나온다. 그래서 **시간을 임의로 정해 테스트할 수 있는 개발용 스위치**를 먼저 둔다.

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 서버: 앱이 예측을 받아갈 수 있게 만들기, 운영 데이터 규모 확인 | **완료** |
| 2 | 앱: 가게별 예측 받아오기, 90초 갱신, 예측 대상 판정, 개발용 시간 스위치 | **완료** |
| 3 | 홈: 섹션 배치, 정렬, `예측 · ○○` 배지 (더보기 목록 포함) | **코드 완료, 실기기 확인 대기** |
| 4 | 상세페이지: 확률 숫자와 안내 문구 | **코드 완료, 실기기 확인 대기** |
| 5 | 지도: `예측` 태그를 먼저 실제 앱에서 확인 → 3색 마커, 카드 배지와 설명 한 줄 (범례에는 넣지 않음) | 코드 완료, 실기기 확인 대기 |
| 6 | 지도: `스탬프 2개` 필터 칩 (칩줄 맨 앞) | 코드 완료, 실기기 확인 대기 |
| 7 | 지표: 예측이 보인 횟수, 눌린 횟수를 어드민에 연결 | 코드 완료, 서버 SQL 실행 대기 |
| 8 | 점검 | 대기 |

**8단계 점검 항목**
- 시각 경계: 11:29 / 11:30 / 12:59 / 13:00
- 제보 개수 경계: 2건 / 3건
- 마지막 제보 경과: 29분 / 31분
- 예측 가게에 새 제보가 들어왔을 때 확정 제보로 바뀌는지
- 주말에 예측이 안 나오는지

## 11. 정해진 것과 남은 것

**정해진 것**
- 최소 표본은 3건 그대로 둔다.
- 11:30 ~ 12:00 구간 포함, 13:00 이후는 제외한다.
- 약간혼잡은 0.6점으로 한다.

**구현하면서 정할 것**
- 갱신 간격 90초가 적당한지
- 지도 `예측` 태그의 크기와 위치 (5단계에서 실제 앱으로 확인)

## 12. 운영 데이터 현황 (1단계에서 확인)

점심 가게 47곳 중, 구간별로 제보가 3건 이상인 가게 수는 이렇다.

| 구간 | 11:30 | 11:45 | 12:00 | 12:15 | 12:30 | 12:45 |
|---|---|---|---|---|---|---|
| 가게 수 | 30 | 13 | 41 | 41 | 29 | 15 |

- 대부분 데이터 확보용으로 넣은 관리자 제보 전용 계정의 제보다. 의도된 상태다.
  (예: 11:30 구간은 제보 116건 중 108건)
- 일반 이용자 제보가 충분히 쌓이면 이 비중을 다시 점검한다.
- 서버에서 확인한 결과, 시간 경계(11:29 / 11:30 / 12:59 / 13:00)와 주말, 확률에 따른 섹션 구분이 모두 기획대로 동작한다.
