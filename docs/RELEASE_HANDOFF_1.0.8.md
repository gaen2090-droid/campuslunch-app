## 2. 빌드 전에 확인할 것

### 버전 번호 (가장 중요)
- 현재 `pubspec.yaml`: `version: 1.0.8+20` (이름 `1.0.8`, 빌드 번호 `20`)
- **스토어에 이미 올라간 값보다 높아야 합니다.**
  - Play Console: 이미 올라간 버전 코드(`+` 뒤 숫자) 이하는 업로드가 거부됩니다.
  - App Store Connect: 같은 버전 이름이면 빌드 번호가 이전보다 커야 합니다.
- 두 스토어 콘솔에서 현재 값을 확인한 뒤 `pubspec.yaml`을 맞춰 올려 주세요.
- 참고: 스토어 버전 이름이 두 스토어에서 서로 다르게 올라가 있는 상태입니다
  (iOS 공개 조회 기준 1.0.4, Android 1.0.5라고 전달받음). 같은 버전으로 맞추는 것을 권장합니다.

### 의존성
- 새로 추가됨: `in_app_update`, `package_info_plus`
- 빌드 전 `flutter pub get`을 실행해 주세요.
- `file_picker`는 8.x 고정입니다 (기존 설정 유지).

### DB (이미 완료)
- `supabase/app_version_stats.sql` 실행 완료. 새 빌드가 나가기 전에 DB 작업이 끝나 있어야 합니다.
- 어드민웹(회원 > 앱 버전 현황)도 배포 완료.

## 3. 업데이트 팝업이 뜨는 조건

### Android
- Play 스토어가 띄우는 **시스템 팝업**(유연한 업데이트)입니다. 문구/디자인은 바꿀 수 없습니다.
- 업데이트를 누르면 앱 안에서 백그라운드로 다운로드하고, 끝나면 "업데이트 준비가 끝났어요 [재시작]" 스낵바가 뜹니다.
- **Play 스토어로 설치한 앱에서만** 동작합니다. 직접 설치한 APK, 디버그 빌드에서는 뜨지 않습니다.
- 기준은 버전 이름이 아니라 **버전 코드**입니다 (Play가 비교).

### iOS
- 앱이 직접 만든 팝업입니다 ("새 버전이 나왔어요 / 더 좋아진 캠퍼스런치를 사용해보세요").
- App Store 조회 API(`itunes.apple.com/lookup?bundleId=com.campuslunch.app&country=kr`)의
  버전이 설치된 앱 버전보다 **높을 때만** 뜹니다.
- 기준은 버전 **이름**(`1.0.x`)입니다. 빌드 번호만 올리고 이름을 안 올리면 뜨지 않습니다.
- "업데이트" 버튼은 App Store의 캠퍼스런치 페이지로 이동합니다.

### 공통
- 앱 실행당 1번만 확인하고, "나중에"를 누르면 24시간 동안 다시 묻지 않습니다.
- 조회/통신에 실패해도 조용히 넘어가고 앱 사용에는 영향이 없습니다.

## 4. 출시 후 확인

- [ ] 어드민웹 > 회원 > 앱 버전 현황에 새 버전이 나타나는지
      (사용자가 새 빌드로 업데이트해서 앱을 열어야 반영됩니다. 그 전에는 "미확인"으로 보입니다.)
- [ ] Android: 이전 버전이 설치된 기기에서 앱을 열면 Play 업데이트 팝업이 뜨는지
      (내부 테스트 트랙에 낮은 버전을 먼저 설치해 확인하는 것을 권장)
- [ ] iOS: 이전 버전이 설치된 기기에서 팝업이 뜨고 "업데이트"가 App Store로 이동하는지
- [ ] 컬렉션 상세에서 한줄평이 2줄까지 잘 표시되는지 (긴 한줄평이 있는 컬렉션으로 확인)
